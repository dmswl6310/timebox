# Timebox

브레인덤프에서 할 일을 꺼내고, 오늘의 핵심 업무 3가지를 정한 뒤, 15분 단위 일정에 배치하고 회고하는 반응형 타임박싱 웹서비스입니다.

## 현재 구현된 기능

- 이메일 기반 Supabase 회원가입·로그인
- 날짜별 계획 작성과 이전/다음 날짜 이동, 전날 미리 만드는 내일 계획
- 완료 전까지 날짜와 무관하게 유지되며 제목·태그로 즉시 찾을 수 있는 브레인덤프
- 작업별 사용자 정의 태그와 예상 시간 설정, 마이페이지에서 내 태그 추가·관리
- 오늘의 핵심 업무(MIT) 최대 3개 선택 및 일정표 강조
- 15분·30분 눈금의 드래그 앤 드롭 일정 배치
- 기상 시간부터 다음 날 오전 1시까지 이어지는 일정표와 자정 이후 일정 저장
- 작업명에 집중한 간결한 타임블록 UI와 블록 이동, 길이 조절, 바깥 드롭 삭제, 버퍼 추가, 완료 및 실제 수행 시간 자동 기록
- 타임블록을 시간표 밖으로 끌어 일정만 제거하거나, 브레인덤프 작업 삭제 시 연결된 타임블록까지 함께 정리
- 계획 확정 뒤 `계획 변경` 모드에서 여러 일정을 한 번에 조정하고, `변경 확정` 시 공통 이유를 한 번만 입력
- 우선순위·브레인덤프 영역 숨김과 접이식 선택 블록 도구로 시간표에 집중하는 간결한 화면
- 일기와 기분 자동 저장
- 오늘·주·달력 월·연간·전체 통계, 완료율·일기·기분을 표시하는 월간 기록 달력, 태그별 계획·실제 시간 비교와 원래 날짜를 바로 여는 기록 검색
- 장기간 기록도 누락되지 않도록 페이지·ID 묶음 단위로 불러오는 전체 기록 조회
- 월요일부터 일요일까지의 주간 집중 시간 목표 설정과 실제 수행 시간 달성률
- 30일 동안 유효한 읽기 전용 일정 공유 링크와 생성·만료·취소 관리
- 종이 플래너 모드와 일잘러 모드
- 프로필 버튼으로 여는 마이페이지에서 계정 확인, 태그 추가, 화면 모드·기상 시간 변경, 로그아웃

## 기술 구성

- Next.js App Router / React Server Components
- React 19 / TypeScript
- Zustand
- `@dnd-kit/react`
- Tailwind CSS 4와 전역 디자인 시스템
- Supabase Auth / Postgres / Row Level Security

초기 데이터와 인증 확인은 Server Component에서 처리하고, 드래그 앤 드롭과 편집 상태만 Client Component에서 관리합니다.

## 로컬 실행

Node.js 22.13 이상이 필요합니다.

```bash
npm install
copy .env.example .env.local
npm run dev
```

`.env.local`에 다음 값을 입력합니다.

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

Supabase SQL Editor 또는 CLI에서 `supabase/migrations`의 `001`부터 최신 파일까지 순서대로 적용합니다. 이미 운영 DB에 적용한 마이그레이션은 수정하지 말고 새 번호의 파일을 추가합니다.

Supabase Auth의 Redirect URLs에는 로컬 주소와 배포 주소의 `/auth/callback`을 등록해야 합니다.

마이그레이션 적용 후 다음 읽기 전용 SQL을 실행하면 주간 목표, 변경 이유, 공유 함수와 주요 RLS 상태를 한 번에 확인할 수 있습니다.

```text
supabase/scripts/verify_schema.sql
```

결과의 모든 `status`가 `ok`여야 합니다.

## 테스트 데이터 초기화

로그인 계정과 DB 구조는 유지하고 Timebox 앱 데이터만 전부 비우려면 Supabase SQL Editor에서 다음 파일을 수동 실행합니다.

```text
supabase/scripts/reset_app_data.sql
```

이 파일은 복구할 수 없는 `truncate` 작업을 수행하므로 자동 마이그레이션에 포함하지 않습니다. 실행 후 파일 하단의 확인 쿼리가 모든 앱 테이블을 `0건`으로 표시하는지 확인합니다.

  api/shares/route.ts         공유 토큰 생성 API
  api/shares/[shareId]/       공유 링크 취소 API
  api/goals/weekly/           주간 목표 조회·저장 API
  share/[token]/page.tsx      읽기 전용 공개 일정

  server-data.ts              플래너 초기 데이터 조회
  persistence.ts              Supabase 쓰기 작업
  records-data.ts             통계·검색 데이터 조회
  store.tsx                   Zustand 도메인 상태와 명령
  tag-utils.ts                태그 정규화·색상·추천 규칙
  timebox-dashboard.tsx       클라이언트 UI와 상호작용

supabase/scripts/             필요할 때만 실행하는 운영·초기화 SQL

날짜별 플래너는 `/?date=YYYY-MM-DD`로 열립니다. 날짜 파라미터가 없으면 서울 기준 오늘 계획을 엽니다.

## 핵심 데이터 규칙

- 하나의 작업은 한 날짜의 활성 시간표에 한 번만 배치합니다.
- 태그는 사용자가 직접 만들고 수정할 수 있습니다. 앞뒤·연속 공백을 정리해 최대 30자로 저장하며 같은 이름에는 일관된 색상을 적용합니다.
- 새 태그는 브레인덤프 작성·할 일 수정 화면에서 직접 입력하거나 마이페이지의 `내 태그`에서 먼저 추가할 수 있습니다. 작업에 아직 연결하지 않은 태그도 계정에 보존됩니다.
- 마이페이지의 기상 시간은 계정의 `profiles.day_start`에 저장되며, 빈 시간표의 첫 자동 배치와 일정표 시작 시각에 적용됩니다. 기존에 더 이른 블록이 있으면 그 블록은 숨기지 않습니다.
- 오늘 내일 계획을 미리 확정할 수 있지만, 미래 계획의 일과 완료는 해당 날짜가 된 뒤에만 가능합니다.
- 일정 블록 길이가 바뀌면 연결된 작업의 예상 시간도 동기화합니다.
- 반대로 브레인덤프에서 배치된 작업의 예상 시간을 바꾸면 연결 블록 크기도 동기화합니다. 확정 후에는 `계획 변경` 모드에서 수정하며 다른 블록과 겹치는 변경은 적용하지 않습니다.
- 완료할 때 실제 시간을 따로 입력하지 않았다면 계획한 시간을 기본 실제 시간으로 저장합니다.
- Supabase 쓰기는 사용자 조작 순서대로 실행해 빠른 연속 편집의 저장 순서가 뒤바뀌지 않게 합니다.
- 전체 기록은 고정 건수로 잘라내지 않고 500건씩 페이지 조회하며, 긴 `in` 쿼리를 피하도록 ID를 100개씩 나눠 불러옵니다.
- 같은 시간에 블록을 겹쳐 배치하지 않습니다.
- 일정은 계획일의 다음 날 오전 1시까지 배치할 수 있으며, 자정 이후 블록은 DB에는 실제 다음 날짜 시각으로 저장하고 화면에서는 같은 계획일의 연속 구간으로 복원합니다.
- 완료된 작업은 브레인덤프에서 숨기지만 기록과 일정에서는 유지합니다.
- 삭제한 블록은 물리 삭제하지 않고 `cancelled` 상태로 보존합니다.
- 일정 블록만 삭제하면 작업은 브레인덤프에 남고, 브레인덤프 작업을 삭제하면 같은 날짜에 연결된 활성 블록도 함께 `cancelled` 처리합니다.
- 계획 확정 후에는 `계획 변경`을 눌러 일정 여러 개를 추가·이동·크기 조정·삭제하고, `변경 확정` 때 변경 전체의 공통 이유를 한 번 입력합니다. 중간 편집은 기록하지 않고, `일과 완료`를 누르면 확정본과 최종본을 비교해 최종 추가·이동·크기 변경·삭제와 공통 이유를 `schedule_change_events`에 기록한 뒤 그날을 잠급니다.
- 공유 토큰 원문은 저장하지 않고 SHA-256 해시만 저장합니다.

## 검사

```bash
npm run typecheck
npm test
npm run lint
npm run build
npm audit --audit-level=high
```

`npm test`는 Vitest로 일정 배치, 15분 이동, 중복·겹침 방지, 블록 크기와 작업 예상 시간 동기화, 확정 후 변경 이유, 핵심 업무 제한을 검사합니다. 개발 중 테스트를 계속 실행하려면 `npm run test:watch`를 사용합니다.

배포 전에는 로그인, 날짜 이동, 계획 확정, 중간 일정 조정, 오늘 일과 완료, 최종 차이 기록, 일기 저장, 기록 조회, 공유 링크를 실제 Supabase 계정으로 한 번씩 확인합니다.
